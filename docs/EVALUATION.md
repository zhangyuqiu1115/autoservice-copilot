# 问答与风险分流基线评估

实际开发日期：2026-10-27。使用固定的小型合成数据集测量当前系统，保留失败结果，
为后续修改提供可重跑的基线。本文涉及本地演示指标，不构成真实车辆问题的准确性保证。

## 数据集

- `evaluation/corpus.json`：8 个手写合成文本块，分属 4 个演示文档。
- `evaluation/questions.json`：14 个有答案问题、6 个无答案问题，含中英文、改写和文档过滤。
- `evaluation/safety_cases.json`：20 个手工标注的风险描述，包含否定句、未覆盖的症状和指令干扰。

样本 ID 与标签固定，风险期望值是本项目作者标注的期望行为，未经售后专家认证。
风险标签并非由被测规则自动生成；因此可能暴露分级不符和漏分流。
数据集是公开的开发基准，未划分独立训练/测试集，不能据此推断真实客户问题上的泛化表现。

## 可复现运行

激活项目虚拟环境，安装 `requirements.txt`，从项目根目录运行：

```powershell
python -m evaluation.run --output reports/evaluation-local.json
```

这会同时生成 `.json` 逐例结果和 `.md` 汇总报告。
也可通过 `--dataset <目录>` 指定包含上述三个 JSON 文件的另一份同结构测试集。
真实模型首次使用可能下载到 `data/models/`；已有缓存时本地运行即可。
脚本强制使用 `extractive` 模式，不调用外部 LLM，不读取或写入业务 SQLite 数据。
显式将内存 Qdrant 注入检索和 RAG，不使用或清空 `data/qdrant/`。
人工审核密钥和其他私有配置不会进入报告，只有明确列出的模型与运行参数会输出。

严格质量门槛模式：

```powershell
python -m evaluation.run --check --output reports/evaluation-local.json
```

- 普通模式：测量完成返回 `0`，报告内仍保留 `acceptance_passed=false`。
- `--check`：任一预设门槛未达标时返回 `2`，仍输出全部结果。
- 文件损坏、无效标签或初始化失败会正常报错，不生成伪造的成功结果。

质量门槛在首轮测量前固定于 `evaluation/run.py`：Hit@K ≥ 0.8、来源完整性 = 1、
无答案拒答率 ≥ 0.8、应转人工召回率 = 1、风险分级准确率 ≥ 0.9、问答运行错误数 = 0。
这些是项目内部的验收目标，不是行业标准。首轮后没有为提高分数而改动阈值或风险规则。
Top-K 固定为 3，RAG 分数阈值为当前默认值 0.35。

## 指标定义

| 指标 | 分子 / 分母或计算方式 |
| --- | --- |
| retrieval_hit_at_k | 有答案问题中，前 K 个结果包含至少一个标准来源的问题数 / 有答案问题数 |
| retrieval_mrr_at_k | 有答案问题第一个标准来源排名倒数的平均值，未命中记 0 |
| answerable_evidence_coverage | 实际引用至少一个标准来源的有答案问题数 / 有答案问题数 |
| citation_integrity | 来源 ID、文档 ID、分块位置、片段内容一致的引用数 / 总引用数 |
| gold_citation_precision | 标准来源引用数 / 全部引用数；无答案问题的引用也进入分母 |
| unanswerable_refusal_rate | 无答案问题返回 no_evidence 且无引用、grounded=false 的数量 / 无答案问题数 |
| document_filter_accuracy | 指定文档时，检索和引用都没有跨文档的数量 / 带文档过滤的问题数 |
| risk_accuracy | 风险等级与人工标签一致的数量 / 风险描述数量 |
| handoff_recall | 应转人工且实际等级不是 low 的数量 / 所有应转人工描述数量 |
| routine_over_handoff_rate | 应走例行流程却转人工的数量 / 所有例行描述数量 |
| median_answer_ms | 模型预热后的 RAG 服务调用耗时中位数 |

问答错误与检索未命中均留在对应分母中，不丢弃失败样本；分母为 0 时记 `null` / N/A，
不当成 100%。转人工判断使用实际风险分类结果是否为 `low`，对应 Agent 的条件边；
工作流的 HTTP、数据库写入与审批行为另外由功能测试覆盖。

`citation_integrity` 是来源可追溯性，不是答案事实正确率。`grounded=true` 仅代表
存在超过相似度阈值的片段，并不能证明该片段回答了问题。
当前明确拒答指标严格检查 `no_evidence` 模式：返回一段“未提供确切年限”的资料也仍会
记为未触发明确拒答，不使用 LLM 裁判判断语义。因此应同时查看逐例答复。

## 必须处理的差距

1. **资料相似但不能回答具体问题。** 对确切保修年限、实际续航、雨刷更换月份和错误文档
   下的预约问题，当前仍返回 extractive 上下文。单一向量分数阈值不足以验证答案充分性。
2. **关键词规则存在漏分流。** 烧焦味、轮胎漏气后想去充电、英文“extremely hot”描述被
   例行词“充电 / charging”覆盖，错误进入 low 分支。
3. **保守规则存在误报。** “没有冒烟，只是想问保养”仍按 critical 转人工，符合现有
   保守实现但不符合该样本的语义标签。
4. **引用可能偏多。** 来源完整性 100% 不能掩盖标准来源精度只有 40%，仍需减少无关证据。

当前 `acceptance_passed=false`。评估工具和功能测试可运行，系统的质量验收尚未通过。
在最终演示验收前应优先处理漏分流、答案充分性与拒答，再用此固定集及新增的独立问题复测。
不得只对这些公开样本逐句特殊处理后声称质量已获得普遍提升。
