# 拒答与风险分流修复

实际开发日期：2026-10-27。针对首轮评估发现的问题增加通用检查，保留原始失败报告、
标签、Top-K、相似度阈值和质量门槛，并将修复后的结果分别保存。

## 改动与作用

`app/services/evidence_gate.py` 在相似度阈值之外增加以下检查：

- 使用中英文主题锚点筛选证据，区分保修、预约、续航、滤芯、雨刷、胎压和充电。
- 询问年限、周期、距离、压力、费用时，相关句必须给出对应数值与单位。
- 排除明确未提供该事实的语句，以及把购车日期误当作保修年限的情况。
- 预约或申请资料问题要求有提供/准备等动作及具体材料或信息字段。
- 静态手册不能确定特定车辆此刻的实际续航，对这类定量问题明确拒答。
- 上下文截断后再次检查，防止用被截掉的数值支撑剩余引用。
- 不足时返回 `no_evidence`，不把不合格材料交给外部 LLM。

过滤发生在构建回答和引用之前，避免无关文本消耗上下文预算。未知主题仅在有足够词汇
重合时保留；这可能增加对新领域或跨语言未知主题的拒答。

`app/services/safety.py` 增加烧焦/焦糊气味、车胎失压/爆胎、中英文明显过热、白烟/黑烟等
症状表达，仍按最高等级优先处理，且先合并空白以支持换行描述。
规则仍保守处理否定句，不尝试通过简单否定词删掉潜在风险。

## 新增资料与问题验证

`evaluation/validation/` 使用不同合成资料：7 个文本块、13 个有答案问题、7 个无答案问题，
以及20个风险描述。保修年限、检查周期、续航与胎压数值均为明确标记的虚构值，
用于验证有数据时仍能回答，而不是对所有数量问题一律拒答。

- 检索与标准来源覆盖：12/13，约 92.3%。
- 标准来源引用精度及来源完整性：100%。
- 明确拒答：7/7 = 100%。
- 风险分级：19/20 = 95%；应转人工召回：15/15 = 100%。
- 两个集都通过原先固定的质量门槛。

报告：[新增集逐例汇总](../reports/evaluation-2026-10-27-validation.md)。
保修申请材料问题未检索到正确文本块，系统拒答而没有引用无关材料；该失败仍在报告中。

新增集在本次开发中用于补充验证，包括发现并修正“保修里程上限不能作为续航证据”的主题
歧义。因此它属于开发验证集，不是第三方盲测或严格独立的 held-out 测试。
这些结果不能推出真实客户问题上的准确率，也未评估外部生成模型的事实正确性。

## 剩余边界

- 两个风险集各有一条否定风险描述被保守转人工，没有为提高分数而取消这项策略。
- 事实覆盖检查属于规则启发式，尚不能完整理解所有条件、否定、实体和跨句关系。
- 表格、多段才能拼出的事实以及未收录主题可能被过度拒答；已识别主题也可能仍有覆盖不足。
- 只验证资料里存在可引用内容，不能证明来源真实或适用于提问车辆。
- 最终答复仍需人工审核；不得把上述合成结果作为真实车辆维修判断依据。
